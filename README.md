# Steam recommender — frequent itemsets (Cemile)

Part of our DTU *Computational Tools for Data Science* group project (Steam game recommender).
This part treats each player's library as a market basket and uses **A-Priori** (own implementation,
checked against `mlxtend`) to find association rules such as "owns X + Y → owns Z", which are then used as an
explainable recommender and evaluated against a most-popular baseline.

## Files
| File | What it is |
|---|---|
| `01_frequent_itemsets.ipynb` | Full pipeline: loading, cleaning, A-Priori, rules, evaluation |
| `outputs/clean_baskets.parquet` | Cleaned library data, one row per (user, game): `user_id, appid, name, playtime_forever` (all owned games) |
| `outputs/cleaning_map.json` | Which appids were removed (betas, test servers, SDKs …) and which were merged into which game |
| `outputs/split_users.json` | Shared train/test split of users (seed 42) — use the same test users so results are comparable |
| `outputs/rules_test_results.csv` | Test-set results (Precision/Recall/NDCG@10, coverage, popularity) |
| `outputs/alpha_tradeoff.png` | Accuracy vs. diversity trade-off figure |

## Using the shared data
```python
import pandas as pd, json
df = pd.read_parquet("outputs/clean_baskets.parquet")   # game ID = Steam appid (int)
played = df[df.playtime_forever > 0]                     # or use df for "owned"
split = json.load(open("outputs/split_users.json"))
test_users = set(split["test"])
```
The split contains the 68,255 users with at least one *played* game.

## Reproducing
The raw data (`australian_users_items.json`, UCSD Steam dataset, 553 MB) is not in the repo because of
GitHub's file size limit. Put it next to the notebook and run all cells (Python 3 with pandas, numpy,
matplotlib, mlxtend, pyarrow). `outputs/association_rules.csv` (106 MB) is regenerated by the notebook.
